=====================================================================
【二】硬约束（先读，违反即失败）
=====================================================================

1. 无真机边界
   当前无真机。本实验的所有执行环节只能落在：离线数据集回放、mock 位姿流、MuJoCo/仿真场景、
   ROS2 离线 bag 回放。禁止声称完成真机实验；任何涉及真实机器人运动的步骤只输出「流程 + 安全门禁清单」，
   不实际下发运动指令。

2. 动作下发默认关闭
   `src/infer/execution_loop.py` 默认只把动作写入日志/文件，不对外发布控制指令。
   只有显式配置 `infer.allow_command_publish: true` 且完成安全门禁（急停可达、watchdog 生效、
   限幅限速参数已加载、人员持停）后才允许发布；该开关与门禁结果必须写入日志与 manifest。

3. 双 Python 环境隔离
   ROS2 / Cartographer / TF 相关代码使用 ROS2 Lyrical 的系统 Python（`source config/ros2_env.sh`）；
   训练与推理使用 conda `unitree_rt`（Python 3.12）。
   禁止在系统 Python 里 pip 安装 torch，禁止在 conda 环境里装 rclpy。
   两者之间的位姿数据通过 `pose stream`（UDP/JSONL 文件）传递，见【六】6.5 与【五】5.6。

4. DDS 与网络约束
   ROS2 侧默认 `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`；ROS2 DDS 与 Unitree 原生 DDS 必须隔离
   domain 与网卡；仿真场景只用 `lo` 且使用与实机不同的 domain（如 1）。
   任何"话题收不到"的问题，先按 domain → 网卡 → 消息类型 的顺序排查，再怀疑代码。

5. 视觉与动作的端到端一致性
   训练与推理必须共用同一份归一化统计（`data/stats/normalization.json`）与同一份图像预处理代码
   （`src/datasets/transforms.py`）；禁止在推理侧凭经验重写归一化、resize、通道顺序或角度单位。

6. CVAE 的推理纯度
   推理阶段不得使用后验编码器（不得把真实未来动作喂进网络）。推理只能使用先验分布
   （取均值或采样）。训练阶段的 teacher forcing 只作用于后验编码器，其边界必须在代码注释中标明。

7. 训练/推理解耦
   推理必须能从 checkpoint 冷启动（新进程加载权重后直接推理），不得依赖训练进程的内存状态。
   checkpoint 必须自带 config hash、数据版本、归一化统计引用与 seed。

8. 零虚构与可复现
   所有指标来自真实运行；禁止手改日志、补图、编造曲线。
   每个实验结果必须可由「config + commit + seed + 数据版本」重新生成，并写入 `docs/experiments.md`。

9. 安全门禁前置
   任何"会动关节/会移动"的验证（含仿真动作执行）在执行前必须写入 `TASK.md` 的检查点并逐条确认：
   急停可达、场地隔离、限速限幅生效、watchdog 生效、仿真场景先行。

10. 唯一部署路径
    本实验工程必须部署到 `<环境与工具根>`。
    源码、配置、数据入口、日志、checkpoint、评测与可视化产物都必须位于该目录内。
    禁止在原 Prompt 目录、`a_Visual_experiment/SLAM/cvae_slam/` 或其他路径创建第二份工程。
    现有 conda `unitree_rt`、ROS2 系统环境与外部大型数据可作为外部依赖复用，
    但只能通过 `configs/paths.yaml` 的绝对路径或可验证软链接引用，不得改变本工程的唯一部署根目录。

4.1 一级目录职责（必须逐字写入 README 的"放什么 / 不放什么"表）

  data/         放：原始 episode、处理产物、划分文件、归一化统计、mock 数据、schema。
                不放：代码、模型权重、日志、临时脚本。raw/ 只读，任何脚本禁止回写。
  src/          放：可被 import 的库与可执行入口（datasets/models/slam/train/infer/utils）。
                不放：数据、权重、超参值（超参一律进 configs/）。
  configs/      放：YAML/Lua 配置与消融覆盖文件；唯一超参事实源。
                不放：代码逻辑、路径硬编码以外的运行状态。
  scripts/      放：命令入口与编排（幂等、可重复执行、无魔数）。
                不放：算法实现（算法必须在 src/ 内，脚本只调用）。
  tests/        放：单元/契约/回归测试；不放：需要真机或长训练的用例。
  docs/         放：设计、算法笔记、数据字典、SLAM 集成说明、实验登记、排错手册。
  evidence/     放：截图与配对日志的索引；编号与阶段一一对应。
  logs/         放：运行日志与指标 JSONL；按阶段编号命名，禁止手工编辑。
  checkpoints/  放：模型权重与 meta.json；禁止把同一权重复制到多处。
  outputs/      放：图、表、评测与消融结果；可由 logs/ 与 checkpoints/ 重建。

4.2 依赖方向（架构约束，违反即返工）

  scripts/ ──▶ src/train、src/infer ──▶ src/models、src/datasets、src/utils
  src/slam（ROS2 侧进程）──▶ pose stream ──▶ src/slam/pose_stream.py ──▶ src/datasets、src/infer

  - `src/models/` 不得 import `src/datasets/`、`src/train/`、`src/infer/`；
  - `src/datasets/` 不得 import `src/models/`；
  - `src/slam/` 不得 import `src/models/`；
  - `src/utils/` 为最底层，只能被依赖，不得反向依赖其他内部包；
  - 违反依赖方向的 import 必须重构，不允许以"方便"为由保留。

5.2 configs/（唯一超参与路径事实源；代码内禁止硬编码这些值）

      作用：数据与切片契约。字段至少含：图像 resize/裁剪尺寸、通道顺序、颜色空间；

            观测历史帧数 K、动作块长度 H、窗口 stride、控制频率（Hz）、

  configs/model.yaml【必需】
      作用：网络结构超参：视觉主干类型与是否预训练/冻结、多帧聚合方式（last/pool/gru）、
            视觉特征维度、状态编码维度、latent_dim（z 维度）、先验/后验/解码器层数与隐藏宽度、
            dropout、激活函数、输出头形式（每步回归完整动作 vs 预测增量）、参数量统计开关。
      约束：任何结构变更必须同步更新 `docs/algorithm_notes.md` 的网络结构图。

  configs/train.yaml【必需】
      作用：训练超参与策略：batch size、epochs/steps、lr、optimizer、weight decay、梯度裁剪、
            混合精度开关、num_workers、seed、重建损失类型与权重、KL 权重 β、
            KL 退火方案（warmup steps + linear/cosine/cyclical）、是否启用 free-bits、
            动作平滑损失权重、时序一致性损失权重、验证周期、checkpoint 周期、
            早停条件（连续 N 次验证无提升）。
      约束：所有损失权重必须可在消融中独立覆盖，无需改代码。

  configs/infer.yaml【必需】
      作用：推理解码与执行策略：checkpoint 路径、latent 使用方式（mean/sample）、采样条数（多模态）、
            每次预测后执行的步数 n_exec、是否启用时间集成及模式与参数（decay/window/min_weight）、
            动作限幅（单步最大位移/旋转/夹爪速率）、速度上限、watchdog 超时、
            闭环最大步数与终止条件、动作发布开关（默认 false）。
      约束：`allow_command_publish` 默认 false；打开时必须同时满足安全门禁配置项。

  configs/slam.yaml【必需】
      作用：SLAM 桥接契约：运行模式（online/replay/mock）、位姿来源（tf / tracked_pose topic）、
            topic 名与消息类型、frame 名（map/odom/base_link）、TF 查询超时、

5.5 src/models/（算法核心）
---------------------------------------------------------------------

  src/models/__init__.py【必需】
      作用：导出 `CVAEPolicy`、`ActionChunker`、`TemporalEnsembler` 等公共类。

  src/models/vision_backbone.py【必需】
      作用：多帧视觉编码：共享权重 CNN 主干（如轻量 ResNet 变体，具体以可用权重与算力为准）+
            多帧聚合（last / 平均池化 / GRU 之一，配置可选）+ 特征投影到统一维度。
            支持多相机输入（按相机分组编码后拼接，或按通道堆叠，二者选一并在配置中声明）。
      约束：输出固定维度特征 `[B, d_v]`；前向内断言输入 shape 与归一化范围；
            冻结/微调由配置控制；不得在内部做 resize（预处理在 datasets 层）。

  src/models/encoder.py【必需】
      作用：CVAE 后验编码器 `q(z | o, s, a_chunk)`：输入视觉特征 + 状态向量 + 未来动作块，
            经 MLP/残差块输出对角高斯参数 `mu, log_var`（各 `[B, latent_dim]`）。
      约束：含 dropout/归一化层；输出 log_var 做 clamp（防数值爆炸）；
            必须写清"仅在训练阶段被调用"的注释。

  src/models/cvae_policy.py【必需（核心文件）】
      作用：策略主体，显式实现并注释以下要素：
            （1）先验网络 `p(z | o, s)`：只依赖当前观测与状态；
            （2）后验网络 `q(z | o, s, a_chunk)`：训练期使用，编码真实未来动作块；
            （3）重参数化采样 `z = mu + exp(0.5 * log_var) * eps`；
            （4）解码器/策略头 `pi(a_chunk | o, s, z)`：输出未来 H 步动作块；
            （5）损失装配：重建损失 + KL 散度（权重与退火来自 train.yaml）；
            （6）teacher forcing 边界：训练用真值动作块进后验，推理只用先验。
      关键接口：
            `forward(obs, state, action_chunk=None, mode="train", sample_z=True)`
            `predict_chunk(obs, state, mode="mean"|"sample", n_samples=1) -> [B,H,d_a]`
            `compute_loss(batch, step) -> dict(recon, kl, reg, total)`
      约束：推理路径不得访问 action_chunk；KL 与重建项必须分别可记录、可单独关闭（供消融）。

  src/models/action_chunker.py【必需（核心文件）】
      作用：动作块的语义与调度（不含神经网络）：
            `ActionSpec(d_a, units, frame, is_delta)`、`build_chunk(actions, t, H)`、
            `ChunkScheduler(H, n_exec)`（决定何时重新预测、执行多少步、何时丢弃尾部）、
            `split_chunk_to_steps(chunk)`。
      约束：与 `window_builder.py` 共用同一套切片语义；
            必须支持"chunk 长度可配置"并在文档中解释 H 对平滑性/响应延迟的影响。

  src/models/temporal_ensemble.py【必需（核心文件）】
      作用：时间集成融合器：维护"最近若干次预测在时间轴上的重叠动作"，
            按权重融合输出当前时刻动作。至少实现并可选：
            （a）uniform-in-chunk（块内均匀权重）；
            （b）exponential decay（`w = decay ** age`，age 按步计）；
            （c）inverse-age（`w = 1 / (1 + age)`）；
            （d）confidence-weighted（按预测对应 chunk 的置信/先验信号加权，可选）。
            接口：`update(chunk, t0, n_exec, meta)`、`action_at(t)`、`reset()`、
            `stats()`（每个 step 参与融合的预测数、权重和）。
      约束：权重必须归一化；冷启动（仅 1 个预测）时退化为直接执行；
            缺步与过期预测必须显式裁剪而非补零；
            融合只作用于"未来将被执行"的步，禁止回改已执行动作。

  src/models/layers.py【可选】
      作用：共享基础块（MLP 构造器、激活、位置/时间编码、权重初始化、重参数化工具函数），
            避免在多处重复实现同一结构。

5.8 src/infer/
---------------------------------------------------------------------

  src/infer/__init__.py【必需】

  src/infer/rollout_policy.py【必需（推理核心）】
      作用：滚动推理：从数据集 episode 或观测流读取观测 → 组成 (o, s) →
            调 `predict_chunk` → 交给 chunk 调度与时间集成 → 输出被执行的动作序列。
            支持开环（预测一次执行整段）与闭环（执行 n_exec 步后用新观测重新预测）两种模式，
            并记录每次预测的耗时、chunk 与融合权重来源。
      约束：推理不得访问后验；所有输出动作必须记录"来源（predict 序号 / 融合权重）"以便复盘。

  src/infer/execution_loop.py【必需（在线执行；默认不下发指令）】
      作用：在线执行循环：读观测 + 读 Cartographer 位姿 → 预测 → 时间集成 →
            限幅/限速/单步增量上限 → watchdog 检查 → 输出动作（默认写文件与日志）。
            含超时处理、异常回调、优雅退出、丢帧降级、掉线保护。
      约束：`infer.allow_command_publish` 默认 false；打开时必须在启动日志中打印安全门禁检查结果；
            任何一次 watchdog 触发都必须立即停止后续动作并记录事件。

  src/infer/offline_eval.py【必需】
      作用：离线评测：在 val/test split 上计算每步与每 chunk 的动作误差、
            平滑度（jerk/差分方差）、多模态命中率、推理延迟分位数（p50/p95）、
            SLAM 位姿参与前后的对比指标；输出表格到 `outputs/eval/`。

  src/infer/replay.py【可选】

【六】关键算法契约（实现前先读，实现后逐条自检）
=====================================================================

6.1 张量契约（字段顺序必须与 configs/data.yaml 和 schema 一致）

  观测图像      images   [B, K, C, H, W]           K 帧历史，C=3，未归一化范围在 transforms 内处理
  多相机        images   [B, N_cam, K, C, H, W]   仅当启用多视角；编码方式在 model.yaml 声明
  状态向量      state    [B, d_s]
                        d_s = 关节位置 + 关节速度 + 夹爪开合 + 末端位姿(或增量) +
                              SLAM 位姿(x, y, sinθ, cosθ[, z, quat]) + 位姿有效性标志 + 时间特征
  动作块        action   [B, H, d_a]              d_a = 平移增量(3) + 旋转增量(3，轴角或 6D) + 夹爪(1)
                                                  若使用关节增量，维度与单位在 data.yaml 声明
  掩码          mask     [B, H]                   末尾 padding 或无效步为 0，损失与集成都要乘掩码
  潜变量        z        [B, latent_dim]

  约定：角度单位弧度；平移单位米；所有"增量"以当前末端位姿为参考；坐标系写在 data.yaml 注释中。

6.2 CVAE 契约

  - 后验：q(z | o, s, a_chunk) = N(mu_post, diag(sigma_post^2))，仅训练时使用；
  - 先验：p(z | o, s) = N(mu_prior, diag(sigma_prior^2))，训练与推理都使用；
  - 重参数化：z = mu + sigma * eps，eps ~ N(0, I)；
  - 重建：L_recon = 掩码加权的 L1/Huber(pred_chunk, gt_chunk)；
  - KL：L_kl = 0.5 * sum(sigma_post^2 + mu_post^2 - 1 - log sigma_post^2)（对 batch 求均值）；
  - 总损失：L = L_recon + beta(t) * L_kl + lambda_smooth * L_smooth + lambda_tc * L_tc(可选)；
  - beta(t)：warmup 后由 train.yaml 指定 schedule（linear/cosine/cyclical）；
  - 训练：teacher forcing 仅体现在"后验吃真值动作块"；
  - 推理：z 取自先验（mean 或 sample），可多次采样以展示多模态；
  - 数值：log_var 必须 clamp；KL 项出现 NaN/Inf 时必须中止并记录，不得用 0 值掩盖。

6.3 动作分块契约

  - 数据侧：滑动窗口 `(obs[t-K+1..t], state[t], action[t..t+H-1])`，stride 来自 data.yaml；
  - 训练侧：以整个 chunk 为监督目标（不是逐步预测）；
  - 推理侧：每 `n_exec` 步重新预测一次，`n_exec <= H`；剩余步数不足时用掩码或提前结束 episode；
  - 一致性：`window_builder.build_chunk` 与 `action_chunker.build_chunk` 必须语义一致（同 stride、同边界规则）；
  - 分析要求：给出 H ∈ {4, 8, 16, 32} 在"重建误差 / 动作平滑度 / 单次推理延迟 / 响应滞后"上的对照结果。

6.4 时间集成契约

  - 维护结构：`deque`，元素为 (chunk, t0_pred, n_exec, meta)；
  - 当前时刻 t 的动作：取所有覆盖 t 的预测步，按权重融合：
      uniform-in-chunk : w = 1（同一 chunk 内每步等权）
      exponential      : w = decay^(t0_pred + i - t) 或按块龄衰减（公式在代码注释中写明）
      inverse-age      : w = 1 / (1 + age)
    action(t) = sum(w_j * a_j(t)) / sum(w_j)；
  - 冷启动：只有 1 条预测时直接输出该预测，权重归一化不产生除零；
  - 过期：t0_pred + H <= t 的预测必须被丢弃；
  - 在线更新：每次新预测到达时更新，不得回改已执行动作；
  - 分析要求：给出"开启/关闭时间集成"与"不同 decay"在抖动指标（动作二阶差分方差）
    与延迟指标（从观测到执行的端到端延迟）上的对照结果，并解释取舍。

6.5 Cartographer → 策略的契约（位姿如何进入状态向量）

  - 数据来源：TF `map → base_link`（经 odom）或 Cartographer 轨迹话题，二选一并在 slam.yaml 声明；
  - 输出结构：`PoseSample(t_capture, t_mono, x, y, z, roll, pitch, yaw, source, valid)`；
  - 进入状态向量的字段（默认）：相对 episode 起点的 `(dx, dy, sin(d_yaw), cos(d_yaw))` +
    线速度/角速度（由相邻位姿差分）+ `valid` 标志位；3D 模式下扩展 z 与四元数分量；
  - 归一化：位置按训练集统计标准化；角度用 sin/cos（禁止直接喂原始弧度做线性归一化）；
  - 失效处理（按顺序）：丢帧 < 容差 → 保持上一有效位姿并置 `valid=0`；
    超过容差 → 该样本标记无效（训练时按配置丢弃或作为无效样本参与，但必须显式声明）；
    桥接整体不可用 → `source=unavailable`，禁止用零位姿；
  - 用途说明：位姿既作为策略输入（提供稳定全局参考），也用于轨迹一致性评估与消融对比。

6.6 时序对齐契约

  - 主时钟：策略时钟（单调时钟）；图像/状态/动作/位姿各自带采集时间戳；
  - 对齐方式：最近邻（默认）或线性插值（位姿），最大容差来自配置；
  - 输出：对齐偏移分布（均值/p95）、超容差样本数、gap 分布，写入 `logs/12_data_check.json`；
  - 门禁：超容差比例超过阈值（默认 5%）时必须先修数据/时钟，禁止直接训练。

6.7 安全与平滑契约

  - 单步动作限幅：平移/旋转/夹爪各自上限，超出即裁剪并计数；
  - 速度上限：相邻执行步的变化率上限；
  - watchdog：观测或位姿超时未更新即停止输出动作；
  - 兜底：任何异常（NaN、shape 不符、checkpoint 不匹配）立即停止当前 episode 并记录，
    禁止带病继续执行。

【八】验证清单（逐条给出命令、预期输出与判据）
=====================================================================

  1) 数据形状检查
     命令：python scripts/12_data_check.py --config configs/data.yaml
     预期：打印 episodes/窗口数/字段形状；JSON 报告无 error 级问题。
     判据：images [K,C,H,W] 与 state d_s、action [H,d_a] 与配置完全一致；无 NaN/Inf。

  2) 前向传播 shape check
     命令：pytest -q tests/test_cvae_shapes.py
     预期：输出 [B,H,d_a]，mu/log_var 形状为 [B,latent_dim]。
     判据：全部通过且无 NaN。

  3) 单 batch 过拟合
     命令：bash scripts/21_overfit_single_batch.sh --config configs/train.yaml
     预期：loss 从初始值显著下降（阈值写在配置里）。
     判据：达到阈值即 PASS；否则先查数据/损失/学习率，禁止继续正式训练。

  4) loss 是否正常下降
     命令：bash scripts/20_train.sh --config configs/train.yaml
     预期：logs/train_metrics.jsonl 中 total/recon/kl 项可分项查看；
            outputs/figures/loss_curve.png 生成。
     判据：total 趋势下降；kl 不发散；beta 退火曲线符合配置。

  5) 预测动作是否平滑
     命令：bash scripts/30_infer_offline.sh --config configs/infer.yaml
     预期：输出抖动指标（动作二阶差分方差）与对比曲线。
     判据：开启时间集成后的抖动 ≤ 关闭时（若不满足，必须在报告中给出解释与证据）。

  6) 推理是否能闭环运行
     命令：bash scripts/31_infer_closed_loop.sh --config configs/infer.yaml
     预期：连续 N 步无中断，输出执行轨迹与延迟统计。
     判据：无异常中断；p50/p95 延迟被记录；watchdog 触发次数为 0（或说明原因）。

  7) SLAM 是否输出稳定轨迹
     命令：bash scripts/42_slam_replay_eval.sh
     预期：outputs/slam/ 下轨迹图 + ATE/RPE 统计。
     判据：轨迹连续无跳变（跳变计数与阈值对照）；漂移指标被量化并记录来源。

  8) 模型输出与 Cartographer 位姿是否时序对齐
     命令：python -m src.utils.time_sync --report logs/slam_align.json（或等价入口）
     预期：输出对齐偏移分布与超容差样本比例。
     判据：超容差比例 < 配置阈值；否则必须先修时钟/缓冲，禁止进入训练与评测。

  9) 复现性
     命令：同 config + 同 seed 重跑一次训练子集与推理。
     预期：指标在配置声明的误差带内一致。
     判据：结果一致或差异有解释（非确定性算子、线程数等），并写入 docs/experiments.md。

  10) 工程一致性
     命令：pytest -q；python -m compileall src
     预期：测试全绿；无 import 错误。
     判据：依赖方向未违反；无硬编码超参；配置驱动全流程。

  常见报错与排查方向：
    话题收不到        → domain / 网卡 / RMW / 消息类型（先最小收发验证）
    TF 超时          → frame 名拼写、Cartographer 是否发布、时间戳时钟域
    时间戳不单调      → 采集端时钟与单调时钟混用；统一到策略时钟
    CUDA OOM         → batch size / 图像分辨率 / 多帧数量 / AMP
    loss NaN         → log_var 未 clamp、学习率过大、输入含 NaN
    checkpoint 不匹配 → config hash 或归一化统计哈希不一致（禁止强行加载）

【十】降级链与异常处理（禁止静默失败）
=====================================================================

  1) Cartographer 不可用（ROS2 Lyrical 下无法构建或缺少依赖包）
     降级顺序：a. 官方 ROS2 分支源码构建（记录编译日志与依赖版本）；
               b. 容器/独立环境内运行 ROS1 版 Cartographer + ros1_bridge（记录版本与桥接话题）；
               c. 使用已录制的 bag 离线回放，离线跑 Cartographer 并导出位姿轨迹；
               d. 以上皆不可行 → `mock` 位姿流（标 MOCK）。
     每一级都必须记录：尝试命令、报错、耗时、结论；最终采用的级别写入 README 与 manifest。

  2) ROS2 不可用 → 训练/推理仍必须可跑（离线数据集 + mock 位姿），SLAM 相关项标 DEGRADED。

  3) 无 GPU / torch 不含 sm_120 → 允许 CPU 小规模跑通全流水线并标 BLOCKED（GPU 项），
     报告必须区分"流水线可运行"与"GPU 训练已验证"。

  4) 无真实数据 → mock 数据可用，但所有结论必须标 MOCK，并说明合成规则与真实场景的差异。

  5) 运行期异常
     - NaN/Inf：立即停止当前 episode，打印触发位置与输入统计；
     - 观测超时/watchdog：停止动作输出并记录事件；
     - 位姿丢失超限：该样本标无效，不参与训练与评测；
     - 权重/配置不匹配：拒绝加载并给出期望与实际 hash；
     - OOM：按配置阶梯降低 batch/分辨率并重试，重试次数与结果入日志。

【十三】关键提示（容易踩的坑）
=====================================================================

  - CVAE 的价值在于"同一观测对应多种合理动作"。若数据本身近似单模态，CVAE 收益会很小；
    必须在 mock 数据中显式构造多模态，并在报告中说明真实数据的模态情况。
  - 推理路径混入后验是这类实现最常见的隐蔽错误（表现为指标虚高）；用单元测试与代码审查双重拦截。
  - 动作分块降低推理频率但引入响应滞后；时间集成用平滑性换一部分滞后，必须同时报告两个指标。
  - 时间集成的"补零"是隐蔽 bug：缺步必须裁剪或重归一化，否则会系统性拉向原点。
  - 图像与状态的归一化必须同源；训练侧的统计不能用于推理侧未对齐的字段顺序。
  - Cartographer 的坐标与时间戳是两个独立陷阱：frame 名对了但时间域不同，会让对齐完全失效。
  - 多帧视觉的时间跨度要与控制频率匹配：K 太大会引入滞后，太小则丢信息，需用 A7 消融确认。
  - 离线指标好不等于闭环稳定：必须做闭环滚动测试，并检查动作是否出现低频振荡。
  - 所有"SLAM 提升了性能"的结论，必须用 A4（去掉 Cartographer 输入）对照证明，且两配置只差位姿输入。
  - 记录失败案例与复现失败的实验：它们和成功结果一样是报告素材。
